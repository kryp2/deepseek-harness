# Agent Note: 组合 Peck 发行版与计量模型路由

Status: proposed

[English](2026-08-18-peck-distribution-and-metered-routing.md) | 中文

## 问题

Peck 需要一个 agent 产品，在无需用户为每台设备配置每个提供方的前提下，使用个人模型订阅、用户自有 API 凭据和商业计量模型调用。现有 Peck 工作已经横跨 DeepSeek Harness fork、网关、BRC-100 钱包基础设施、支付通道合约、收据实验和加密存储。把这些部分视为一个无差别的 fork 会增加上游同步难度，并让钱包、提供方和产品策略泄漏到 Harness 核心中。

这些访问方式也有不同的授权和计费规则。个人编程订阅可以允许交互式本地使用，同时禁止共享后端。用户 API 密钥仍归用户所有，不能成为 Peck 库存。只有符合商业条款的 Peck 付费 API 账户才能服务多个用户，并且需要精确、可审计的收费。在一个界面中呈现三种方式不能抹去这些差异。

提供方名称和标称 token 价格不足以支持公平路由。路由可能在缓存价格、输出价格、上下文分层、时间窗口、工具支持、用量报告、保留策略和实测任务成功率上有所不同。静态最便宜模型列表会过时，并可能选择只对错误请求构成或错误时段便宜的模型。

跨仓库工作带来第二类协调风险。当前 Harness 分支把通用问题 waterfall 工作与 Peck 品牌混在一起，而支付仓库包含 dirty 或已经分叉的工作。仅凭工作区推断所有权的 agent 可能编辑相同文件、针对不同 wire 字段构建，或覆盖未提交工作。

## 提案

现有 `kryp2/deepseek-harness` fork 将继续作为唯一的 Peck Harness 产品仓库。它通过明确的上游同步 PR 跟踪 `deepseek-ai/deepseek-harness`，并将 Peck 行为放在插件、能力包和 `peck` 组合包中。canary 期间，内部 `dsh` 包和 CLI 名称保持上游兼容。Peck 专用包保持私有，直到后续发行决策建立明确的 `@peck-to` 发布边界。

非仓库的 `dsh-peck` 脚手架是迁移输入，而不是第二个事实来源。经过验证的钱包和收据代码迁入评审后的 Harness 包。网关、通道、存储和锚定服务保留独立仓库与发行版，并通过版本化 HTTP 和收据字段通信。

第一个 canary 验证一条完整路径：BRC-100 钱包授权消费上限，`deepseek-v4-flash` 通过 Peck 网关服务一个流式请求，网关在服务前预留额度，在服务后按实际用量结算，Harness 验证并显示签名收据和剩余余额。只有这条路径通过 testnet 验收后，才继续提供方扩展、加密会话备份、通道关闭和收据锚定。

## 访问类别

Peck Harness 提供统一的模型选择体验，同时保留三种执行类别：

- **本地套餐。** 个人交互式订阅或原生 coding agent 登录通过获准的工具或 CLI 在用户机器上运行。Peck 绝不把该权益作为公共库存共享、代理或定价。
- **你的 API 密钥。** 用户自有提供方凭据使用钱包派生的 BRC-2 加密，仅在用户机器上解密，并直接发送给该提供方。Peck 可以显示提供方报告的用量，但不为该推理收取 sats。
- **支付 sats。** 可商业计量的 Peck 提供方账户位于 `llm.peck.to` 之后。请求使用预留的通道额度，并返回签名的精确费用收据。

提供方配置声明其执行类别。凭据或路由不能静默跨类别。网关库存拒绝个人套餐凭据，商业付费调用也绝不回退到用户的本地凭据。

## Harness 组合

`peck` 组合包组合钱包身份、Peck 网关适配器、路由与收据展示、消费策略，以及后续的加密备份。钱包身份和凭据所有权构成独立能力，因为会话、备份和其他 Peck 功能会在 LLM 调用之外使用它们。

直接提供方使用现有 `llm-pi-ai` 提供方机制。钱包付费提供方使用一个 `llm-peck` 适配器；提供方专用传输和计费解释留在网关驱动中。添加使用现有提供方协议的模型属于目录变更，而不是新增 Harness 适配器。

Harness 在 agent 会话前解析一次虚拟配置，并固定 `route_id`、`upstream_model_id`、`catalog_hash` 和 `price_schedule_id`。运行中的会话绝不静默更改这些值。如果固定路由不可用，用户批准替代项或启动重新固定的会话。

## 计量请求与收据

网关仅在 SPV 验证后接受 BRC-100 资金证明。转发请求前，它针对通道原子预留该请求允许的最大金额。并发请求不能预留超过可用通道余额的额度。完成、取消、断连、重试和提供方失败都通过同一个幂等请求标识结算或释放预留。

版本化签名收据包含请求 id、通道 outpoint、通道序号、提供方限定路由 id、上游模型 id、目录 hash、价格方案 id、测得的输入／缓存／输出用量、实际 satoshi 收费、响应 hash、时间戳和网关签名。跨语言 schema 和 golden vector 位于负责 Peck overlay schema 的仓库中；Harness 与网关固定同一 schema 修订。

初始预算是用户选择的通道上限，以 sats 和预估法币显示。Harness 在消费达到 50、80 和 95% 时告警。额度耗尽需要明确的新授权；canary 不包含自动充值。

## 目录、路由与调度

每个提供方限定路由记录传输、区域、能力、上下文与输出限制、推理模式、执行类别、保留与驻留声明，以及来源验证时间。其版本化价格方案记录货币、有效区间、缓存命中与未命中输入价格、输出价格、阈值分层、工具费用、UTC 价格窗口、来源 URL 和验证是否为临时状态。钱包付费路由拒绝临时价格。

路由器首先应用能力、执行类别、隐私和消费约束。然后选择通过该任务类别实测质量与协议可靠性下限的最便宜路由。成本估算使用预期缓存与未缓存输入及预期输出，而不是把标称输入输出价格直接相加。测试失败、无效工具行为或低置信度结果可以升级到下一个合格路由；更简单的路由只能在明确的安全任务边界继续。

交互式工作立即分发。标记为灵活的工作在用户机器上保持加密，并在 24 小时内最便宜的合格价格窗口分发。有截止时间的工作在选定截止时间前最便宜的合格窗口分发。提供方时间表保持为 UTC 数据，UI 按用户时区呈现，包括夏令时转换。排队提示词不会仅为了预留未来价格而上传，并且分发前重新报价路由。

DeepSeek V4 Flash 作为首个付费 worker 候选；DeepSeek V4 Pro、GLM-5.2、Qwen、Luna 和后续模型只有在通过约定探测与 Peck 任务评测后，才进入适当的本地或商业类别。订阅额度与 API token 价格保持为不同价格对象。

## 跨 agent 执行

一个 GitHub epic 负责跨仓库依赖图。每个工作项指定一个仓库、一个基础 commit、允许路径、禁止的共享路径、schema 修订、验收命令和一个稳定 agent 身份。每个 agent 使用唯一 worktree，并按工作区署名规则打开 PR。

只有集成负责人更新共享 lockfile、生成目录、组合包结构、schema hash 和最终 snapshot。叶子 agent 返回源代码变更与生成说明，而不竞态修改共享产物。每个仓库的 `IN_FLIGHT.md` 只在最终 PR 中变更一次。

低成本模型负责有界叶子包、提供方 fixture、文档、评测用例和广泛测试扩展。frontier 评审负责协议字段、钱包密码学、SPV 验证、支付并发、结算、智能合约集成和跨仓库验收。生产、基础设施、secret、部署和智能合约 PR 为 Thomas 保持 `[HOLD]`。

实现顺序是上游基线、拆分现有通用与 Peck 变更、冻结 schema 和 golden vector、修复预留与通道开启、连接一个计量 Harness 调用、添加路由与收据展示、完成通道关闭、添加加密备份，最后锚定收据批次。

## 考虑过的替代方案

**再创建一个 Harness fork。** 对现有 fork 再 fork 会重复上游跟踪并分裂产品权威，却没有隔离任何真实部署边界。插件和产品组合包可以在现有 fork 内提供所需分离。

**把 Peck 行为直接放入 Harness 核心。** 这会缩短首次演示，但会把每次上游同步变成产品专用冲突处理，并阻止钱包与支付能力独立演进。

**通过 Peck 代理个人订阅。** 这会混淆用户权益、提供方条款、凭据所有权和公共计费。本地执行可提供统一用户体验，而不把订阅视为转售库存。

**为每个付费提供方添加一个 Harness 适配器。** 这会复制钱包、预留、流式传输和收据行为。一个 Peck 适配器保持钱包约定稳定，而网关驱动负责提供方差异。

**按一个静态最便宜模型排名路由。** 静态排名忽略请求构成、价格窗口、缓存使用、能力失败和不断变化的模型质量。版本化价格与实测任务下限使选择可解释、可复现。

**在付费推理前构建存储和链上锚定。** 这些功能改善最终产品，但不能证明钱包授权、推理、结算和收据验证形成可用路径。

## 验收标准

- fork `master` 跟踪经过评审的上游基线，现有混合分支拆成通用行为和 Peck 发行版 PR，而不是完整合并。
- testnet 用户连接 BRC-100 钱包、授权有界通道、流式执行一个 `deepseek-v4-flash` 请求、支付实际测得用量、验证收据并查看剩余余额。
- 并发、取消、重试、断连、重复和失败请求不能超支或重复收费。
- 本地订阅和用户 API 密钥绝不经过 Peck 付费网关，网关路由不能使用个人套餐凭据。
- 路由解析具有确定性，并固定收据使用的提供方路由、目录和价格方案。
- 定价测试覆盖缓存状态、UTC 价格边界、本地夏令时呈现、目录过期，以及排队与分发之间的价格变化。
- 灵活任务提示词在分发前保持本地加密，并在可能超过授权上限时暂停。
- 每个非平凡实现 PR 都包含其负责的 Agent Note、聚焦测试、面向用户行为的可运行无密钥 snapshot，以及工作区要求的 PR 署名。

## 风险

钱包付费推理形成资金路径，其中预留竞态、不可验证的提供方用量或含糊重试可能导致损失或不公平收费。在并发和幂等性证据通过独立评审前，canary 必须保持有界并优先使用 testnet。

提供方条款和价格方案可能在没有代码变更时改变。过期目录可能错误定价调用或在许可类别之外使用权益，因此商业路由必须在来源验证过期或用量字段无法对账时快速失败。

只有 Harness 进程能够分发任务时，本地调度才能节省费用。产品必须说明此限制，并且在提示词保持本地时不得暗示存在远程常驻队列。

现有仓库包含有价值的 dirty 工作。除非始终强制唯一 worktree、路径所有权和单一共享产物集成负责人，否则跨 agent 速度会增加覆盖风险。
